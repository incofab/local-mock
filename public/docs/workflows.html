First-time Institution Setup

  1. Guest opens /login.
  2. LoginController::create() redirects to /register if public/institution-data.json does not exist.
  3. RegistrationController::store() validates user data, institution code, and platform.
  4. InstitutionHandler::processInstitutionCode() first checks LocalApiFixture. If public/sample-data/local-api-fixture.json exists and matches the submitted institution code/platform, that JSON is used instead of the remote platform.
  5. Without a matching fixture, InstitutionHandler::processInstitutionCode() builds a URL through PlatformUrl::make() and posts to showInstitution().
  6. On success, institution data plus selected platform is saved to public/institution-data.json.
  7. The first admin user is created and logged in.

Sync and Refresh Events

  1. Admin uses Sync Events or Refresh.
  2. EventController calls SyncEvents::all() or SyncEvents::single($event).
  3. WebsiteHelper fetches event data from LocalApiFixture when the current institution matches the fixture; otherwise it calls the remote platform.
  4. Events are stored locally in the events table with JSON event-course payloads.

Download Event Content

  1. Admin downloads an event or downloads by event code. Event-code download upserts the returned event before writing content files.
  2. EventExamsHandler::downloadEventContent() fetches deep event content and registered exams through WebsiteHelper, which may return local fixture JSON.
  3. SyncEvents::saveToFile() deletes any old public/content/event_{id} folder, recreates images and exams, writes course session JSON including OBJ and theory questions, creates or updates pending exam records, writes per-exam JSON, and compiles images.
  4. CompileEventImages extracts image URLs from OBJ question HTML and theory question/answer/marking-scheme HTML, then downloads non-embedded images into the event images folder.
SyncEvents::saveToFile() deletes and recreates the event content folder. Be careful when changing this path or behavior.

Local Practice API Fixture

  1. Run sail artisan app:write-practice-api-fixture to write public/sample-data/local-api-fixture.json.
  2. Initialize the app with institution code PRACTICE-INSTITUTION and platform examscholars-mock, unless custom command options were used.
  3. Sync events and download the mixed practice event. Institution, event list, deep event, event-code download, exam list, and upload calls are served from the fixture JSON.
  4. Start exam MIXED-PRACTICE-001 or create a new exam with event code MIXED-PRACTICE. The startup API returns one course session containing both OBJ questions and theory questions, with answers stripped.

Create Exam By Event Code

  1. Exam client posts to /api/exam/create-by-code with event_code, confirmed student_code, and name.
  2. API\ExamController::createExamByCode() finds the event and calls private createExam().
  3. Creation fails if event content is not downloaded.
  4. Exam number is {event_code}-{student_code}. Existing exams are reused.
  5. New exams get pending status, student JSON, exam course JSON generated from event courses, and a local exam JSON file under public/content/event_{id}/exams.

Start or Resume Exam

  1. Exam client posts to /api/exam/start with exam_no.
  2. API\ExamController::startExam() loads the exam and event.
  3. StartExam::getExamStartupData() verifies downloaded content and starts pending or paused exams.
  4. Exam::markAsStarted() sets status active, start time, null pause time, and end_time from event duration.
  5. ExamHandler::syncExamFile() creates or updates public/exams/exam_{exam_no}.edr. Newly started pending or paused exams overwrite stale tracking files before time validation; active resumes still validate the file's time/status.
  6. StartExam::prepareExam() injects course sessions and strips OBJ answers, theory answers, and theory marking schemes before returning JSON.

Record Attempts and End from Examiner Client

  1. The examiner app posts attempts to public/exam-route/attempt-question.php.
  2. The script calls ExamHandler::attemptQuestion(), which merges attempts into the .edr file. Theory-capable clients should use non-colliding keys such as theory-{question_id}, matching the online examiner pattern.
  3. The examiner app posts to public/exam-route/end-exam.php to mark the file's embedded exam status as ended.

Evaluate, Extend, and Upload

Evaluate

  1. Admin evaluates one exam or an entire event.
  2. EndExam::endExam() refuses already ended or non-active exams.
  3. It compares saved OBJ attempts with downloaded OBJ answers, counts theory questions and obtainable theory marks from the course-session files, stores theory metadata in exam_courses JSON, marks exam ended, and syncs the tracking file.

Extend Time

  1. ExtendExamTime::run() uses the future end time if available, otherwise now.
  2. It sets status active, clears pause time, adds requested minutes, saves, and syncs the tracking file.

Upload

  1. EventExamsHandler::uploadEventExams() chunks event exams by 100.
  2. WebsiteHelper::uploadExams() posts results to the platform.
  3. Exam upload timestamps/messages and the event upload timestamp are updated locally.
