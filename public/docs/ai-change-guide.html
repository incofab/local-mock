Required Reading

  1. Start with public/docs/index.html.
  2. Open the focused docs page for the area you are changing.
  3. Inspect the actual code before editing; the docs are a map, not a substitute for source verification.

Documentation Maintenance Rule

When changing routes, controllers, actions, helpers, support classes, models, migrations, views, public examiner scripts, tests, commands, runtime storage behavior, or file formats, update the relevant page in public/docs in the same change.

If a new subsystem is added, create a new focused docs page and link it from public/docs/index.html and the navigation block used by the other docs pages.

High-risk Areas

  • Do not assume event_courses or exam_courses are normalized relationships; they are JSON-backed in current behavior.
  • Preserve the distinction between downloaded content files in public/content and live attempt tracking files in public/exams.
  • Be careful with SyncEvents::saveToFile(); it deletes and recreates an event content folder.
  • Be careful with raw scripts in public/exam-route; they do not use the Laravel kernel.
  • When changing exam status logic, review Exam, StartExam, EndExam, ExtendExamTime, ExamHandler, admin views, and tests.
  • When changing remote platform integration, update WebsiteHelper, PlatformUrl implementations, tests/fakes, and these docs.
